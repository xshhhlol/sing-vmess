# VMess 服务端特征检查

检查日期：2026-10-30。范围：保持现有 VMess 客户端（sing-box、Xray-core 及基于它们的客户端）兼容，只改服务端协议库。不包括客户端、外层 TLS 终止器和面板。

单次连通、race 检查或写入长度变化只能证明对应的工程属性，不能证明抗识别效果。本项目还没有在真实 DPI 分类器上评测过，因此不承诺"无法识别"。

## 弱点与处理

| 弱点 | 处理 | 剩余边界 |
| --- | --- | --- |
| 认证失败直接断开，且把一次读取不足 100 字节当成坏请求 | 在握手期限内增量读取，收齐 16 字节后识别用户，再读取 AEAD 长度、nonce 和头部。不要求任何 TCP 包或 TLS/WS/gRPC 记录边界。认证失败、时间戳错误、重放、解密失败等仍走统一回落；已读原始字节保留 | 少于 16 字节且不结束发送的输入必须等待剩余数据或期限，否则可能误判合法密文。完整 HTTP 请求可及时回落；不同输入的等待时间仍可能不同，统一处理函数不等于网络行为完全一致 |
| 时间戳容差 ±120 秒，重放缓存只保存 120 秒；解密前登记会让篡改请求占用真实请求的 AuthID | 分片缓存按协议时钟保存到时间戳最后一个有效秒；完整头部验证通过后原子登记。缓存键使用加密 AuthID，避免不同用户的 32 位随机字段相撞；相同请求并发只接受一个 | 缓存只存在于当前 Service 实例内，进程重启、入站重建或多个独立实例不共享状态 |
| 旧版 alterId 没有完整请求重放检测，且增量读取后的回落和预读数据生命周期有问题 | 校验 FNV 校验和；按用户、时间戳、完整头部登记重放，同时允许同一秒内的不同新连接。记录后续原始头部读取，回落不丢字节；成功请求持有预读数据副本 | 只能缓解完整头部的重复重放，不能把旧协议变成 AEAD；仍推荐 alterId=0 |
| 服务启动后才加入 alterId 用户时，认证 ID 定时刷新没有启动 | Start 与 UpdateUsers 都检查是否需要启动刷新，关闭和重复启动受锁保护 | 旧客户端无需改动，时间窗口不扩大 |
| 读请求头没有期限，慢速请求可以长期占住连接 | 握手期限默认 10 秒，配置回落时默认 30 秒，与 trojan 入站一致。超时后，已读字节作为读端已结束的连接交给回落服务。丢弃模式最多同时保留 4096 条连接 | 期限太短会误伤高延迟客户端；固定期限也可能被测量 |
| 客户端可以选 `none` 或未认证的 `aes-128-cfb`，没有外层 TLS 时数据是明文或可被篡改 | 可选 `ServiceWithRequireEncryption`，拒绝这两种加密方式，被拒的请求走回落路径 | 只应在没有外层 TLS 的入站上开启：有 TLS 时 `none` 是合理配置 |
| 下行第一条记录固定 38 字节（AEAD 响应头单独写出）；`Write` 路径下每个分块的 2 字节长度单独写出 | 一次上层写入产生的所有片段，包括待发的响应头，合并成一次底层写入。字节流不变 | 只影响服务端下行。上行由客户端决定，无法从服务端修改 |
| 嵌套 TLS 握手的下行记录长度可被分类 | 可选 `ServiceWithResponseShaping`：每条 TCP 请求的下行数据，前 8–16 条记录拆成 256–1400 字节的随机大小。UDP 和 mux 不拆分，以免破坏包边界。合并写出若发生短写会返回错误，避免静默损坏 | 不隐藏突发规模、往返次数和上行特征；每多一条记录增加分块头、认证标签及已协商填充的开销。写入与 TCP 包/TLS 记录不是一一对应，没有抓包对照时不宣称"像浏览器" |
| 每个连接要逐个试遍所有用户的密钥，垃圾连接可以低成本占满 CPU；并发失败可能同时通过余额检查 | 同一来源最近匹配的用户优先尝试；全量扫描前在锁内预留令牌，成功扫描返还令牌，失败消耗令牌 | 分布在大量 IP 上的攻击仍要付出全量遍历的成本，只是每个 IP 有上限；共享来源的冷用户受同一预算约束 |
| 时间戳校验忽略 NTP 时间 | 改用 `ServiceWithTimeFunc` 提供的时间 | ±120 秒窗口不变 |

## 不能只靠服务端解决的

- **前向保密**：请求密钥由长期不变的 UUID 推导，没有临时密钥交换。要解决只能改协议，客户端也得改。
- **裸 VMess 首包是全随机数据**：这种特征在被动识别时最明显，而首包内容由客户端决定。应改用 TLS、ws+TLS，或换成 VLESS Reality、AnyTLS 等协议。
- **TLS 套 TLS 的上行特征**：里层的 ClientHello 由客户端发出，服务端改不了。
- **老协议（alterId > 0）**：虽然现在会拒绝完整头部的重复重放，但旧式加密和认证的已知局限仍然存在。新配置应保持 alterId 为 0。

## 兼容性验收

- `go test -race .`：用本库自带的客户端，覆盖所有加密方式和客户端选项，TCP 和 UDP 都测；还覆盖老协议、各类探测（短请求、随机数据、TLS 握手、过期时间戳、未知用户、篡改头部、重放）被原样交给回落、沉默探测在期限到达时被交给回落、丢弃模式、强制加密、三条写入路径的合并写入，以及整形的记录大小。
- `cd test/xray && go test -race .`：用 Xray-core v26.3.27 的客户端编码，按 Xray 出站的方式设置请求选项。覆盖四种加密方式、默认开启的全局填充、认证长度，TCP 和 UDP，并分别在开启和不开启整形时测试。`none` 加认证长度这个组合在上游就一直不互通（Xray 对 `none` 忽略这个选项），所以跳过。
- 新增回归：1/7/16/17/33/42/64/99 字节读取限制，TCP/UDP/Mux 的分段头部，alterId 兼容与延迟加入后的时间滚动，篡改/截断请求不占重放缓存，未来时间戳直到第 240 秒的重放拒绝，跨用户 AuthID 区分，64 路并发重放和并发失败扫描限额。
- V2bX 集成测试覆盖 TCP、TLS、WS、gRPC、HTTPUpgrade 的分段请求，TLS 下的 none 客户端，以及 HTTP/1.1、HTTP/2 网站回落。少于 16 字节的不完整输入分别测试发送端半关闭和等待握手期限。

上线前仍应按实际使用的客户端名称和版本做人工验证，并在同一网络下对原版、增强版和普通 HTTPS 做配对抓包。
